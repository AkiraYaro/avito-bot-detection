# Детекция ботов по событиям внутри суточного окна

Для каждой `cookie_id` предсказывается `score` от 0 до 1: вероятность, что кука принадлежит
сервису автоматизированного сбора данных. Метрика: Precision при Recall >= 0.70.

## Результат

| Модель | OOF P@R>=0.7 | ROC-AUC |
|---|---|---|
| baseline из quickstart, 2 признака | 0.102 | 0.628 |
| логрегрессия, 72 признака | 0.510 | 0.903 |
| LightGBM, 30 признаков | 0.744 | 0.929 |

Базовая доля ботов 0.081, поэтому baseline фактически держится на уровне случайного ранжирования.

## Запуск

Положить выданные данные в `data/`, затем:

```bash
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute --inplace solution.ipynb
```

Python 3.14.5, примерно 10 минут. Все `random_state` зафиксированы, повторный запуск даёт тот
же `submission.csv`. Файлы: `solution.ipynb` (весь путь от данных до ответа), `src/features.py`
(построение признаков), `metric.py` (метрика организаторов, без изменений).

## Утечка, которую пришлось исключить

`captcha_shown` встречается только после конца окна наблюдения: внутри окна таких событий ноль.
Признак сильный (среди кук с капчей 77% ботов против базовых 8%) и даёт +0.15 метрики, но он
недоступен в момент принятия решения. Капча это реакция антибота на поведение, которое и
требуется предсказать, поэтому в проде такого признака ещё нет. Не использую. Все признаки
считаются строго внутри окна `[window_start_ts, window_end_ts)`.

## Признаки

72 признака, одна строка на куку:

* тайминг: медиана и перцентили интервалов между событиями, доля длинных пауз, коэффициент вариации;
* курсор: покрытие и разброс координат, только по web/desktop;
* типы событий: доли контактных и вовлечённых действий, просмотров на заход в выдачу;
* разнообразие контента: число категорий и локаций, энтропия, концентрация на одной категории;
* User-Agent и платформа, суточный профиль, доля дубликатов, возраст куки.

Сильнее всего разделяют тайминг и курсор. У ботов медианный интервал 25 с против 59 с у людей,
90-й перцентиль 124 с против 1557 с, то есть длинных пауз у них просто нет. На web/desktop
медиана покрытия курсора у ботов 0.0 против 0.93.

Про качество данных: `platform` записана в разном регистре и нормализуется. Дубликаты событий
не удаляются, среди кук с дублями ботов вдвое больше базового уровня, поэтому из них сделан
признак. `pointer_x/y` пусты на всех мобильных, поэтому признаки курсора считаются только по
web/desktop, иначе они вырождаются в индикатор платформы.

## Валидация

Train занимает 14 суток, test следующие 7, пересечения кук нет.

Метрика определяется несколькими десятками объектов около порога и потому шумная: при подсчёте
по каждому фолду отдельно разброс доходил до ±0.09. Поэтому предсказания собираются OOF по всей
выборке и метрика считается один раз на всех 899 ботах, с повторами по разным сидам, что даёт
разброс ±0.01. Дополнительно обучение на первых 10 днях с проверкой на последних 4, чтобы
поймать деградацию во времени.

## Что пробовал и отклонил

* межкуковые признаки (общий User-Agent за день, популярность объявлений и запросов): прирост
  в пределах шума, а пайплайн заметно усложняется;
* ещё 10 поведенческих признаков: часть прошла отбор по важности, остальные отсеялись;
* `scale_pos_weight` против дисбаланса, сильная регуляризация, ExtraTrees и смеси с ним: без улучшения;
* подбор гиперпараметров: на 2 повторах давал 0.7596, на 6 повторах уже 0.7460 против 0.7430 у
  базовых, то есть почти весь выигрыш оказался отбором максимума из шумных замеров.

ROC-AUC держится на 0.927–0.930 при любом размере набора признаков, поэтому K=30 взят как
компромисс между двумя схемами валидации, без погони за максимумом метрики.

## Ограничения

* разброс метрики ±0.01–0.015, разницу меньше 0.02 между вариантами не считаю значимой;
* разметка это прокси: неизвестные боты попали в отрицательный класс, поэтому настоящий recall
  ниже измеренного;
* модель видит ровно сутки, медленный парсер, размазанный по неделям, останется незамеченным;
* паузы и движения курсора имитируются, если знать, что их считают, поэтому нужно регулярное
  переобучение.
